###### Predicates 
- A predicate specifies a condition that is true, false, or unknown about a given row or group
- Used in `WHERE` clauses
- Ex: `<, >, >=, <=, =, <>`  , `BETWEEN`, `EXISTS`, `IN`, `LIKE`, `NULL`

- Ex:
```sql
SELECT *  
FROM admissions  
WHERE nursing_unit_id = '2EAST'
```

- Ex: 
```sql
SELECT first_name, last_name, patient_weight  
FROM patients  
WHERE patient_weight > (SELECT AVG(patient_weight) FROM patients)
```

- `BETWEEN`
- The BETWEEN predicate compares a value inclusively with a range of values
```sql
SELECT first_name, last_name, patient_height  
FROM patients  
WHERE patient_height BETWEEN 100 AND 105 
/*ABOVE AND BELOW SAME THING*/
WHERE patient_height >= 100 AND patient_height <= 105
```

- `EXISTS`
- The EXISTS predicate tests for the existence of certain rows using a subquery
```sql
SELECT *  
FROM vendors  
WHERE NOT EXISTS (SELECT * FROM  
purchase_orders WHERE purchase_orders.vendor_id = vendors.vendor_id)
```

- `IN`
- The IN predicate compares a value with a set of values
```sql
SELECT first_name, last_name
FROM patients
WHERE patient_id IN (SELECT DISTINCT patient_id FROM unit_dose_orders)
```
- **Subquery Explanation**:
	- `SELECT DISTINCT patient_id FROM unit_dose_orders`: This subquery is selecting the unique `patient_id`s from the `unit_dose_orders` table. The `DISTINCT` keyword ensures that each `patient_id` appears only once, even if the patient has multiple orders.
	- The result of this subquery will be a list of patient IDs who have placed unit dose orders.

- `NOT IN`
```sql
SELECT *  
FROM vendors  
WHERE vendor_id NOT IN (SELECT DISTINCT vendor_id FROM purchase_orders)
```

- `LIKE`
- The LIKE predicate searches for strings that have a certain pattern  
	- % matches any number of characters  
	- _ matches a single character

- `NULL`
	- The NULL predicate tests for null values  
	- Must be used with IS, not =

- `TOP`
- The TOP clause sets a maximum number of rows that can be retrieved
```sql
SELECT TOP 5 *  
FROM patients

SELECT TOP 5 PERCENT *  
FROM patients
```

- `HAVING`
```sql
SELECT nursing_unit_id, COUNT(*)
FROM admissions
GROUP BY nursing_unit_id
HAVING COUNT(*) >= 340
```
- Why `HAVING` instead of `WHERE`?
	- The `WHERE` clause filters rows before aggregation (before `GROUP BY`), but here you need to filter based on the result of the aggregation (the count of admissions). So, you must use `HAVING`, which works after the `GROUP BY` operation.

###### Business Rules
- Specifications that preserve the integrity of a conceptual or logical data model 
- Stored as part of the database 
- Four types 
	- 1. Entity integrity  
		- Each instance of entity must have unique identifier (Primary Key)
	- 2. Referential integrity  
		- Rules governing relationships between entities (Foreign Key)
		- When FOREIGN KEY constraints are specified, typically at table creation, there is an ON DELETE and ON UPDATE parameter that specifies what action happens to rows (or columns) in a related (child) table  
		- The choices are NO ACTION, CASCADE, SET NULL or SET DEFAULT  
		- NO ACTION is the default
	- 3. Domains  
		- Associated with constraints that restrict the values permitted in a column
		- Example: `patient_height > 0`
	- 4. Triggering operations
		- Rules that are invoked on the action of data manipulation operations (INSERT, UPDATE, DELETE)
		- When a required business rule cannot be enforced using the following integrity constraints:  
			– NOT NULL  
			– PRIMARY KEY  
			– FOREIGN KEY  
			– CHECK

###### Stored Procedure Structure 
- Consists of:
	- Procedure Name
	- Set of Optional Parameters 
	- Routine Body 
- Simple Example:
```sql
CREATE PROCEDURE update_items_item_cost  
AS  
UPDATE items  
	SET item_cost = item_cost * (1 + 0.25)  
	WHERE primary_vendor_id = 1;
```

- Example With Parameters:
```sql
ALTER PROCEDURE update_items_item_cost  
	@increase DECIMAL(3, 2),  
	@vendor_id INT  
AS  
UPDATE items  
	SET item_cost = item_cost * (1 + @increase)  
	WHERE primary_vendor_id = @vendor_id;
```

- ###### Side Notes About Alter
	- `ALTER PROCEDURE` allows changing an existing stored procedure  
	- `ALTER TABLE` allows for changing table structure  
		- Adding/Removing/Changing of columns, constraints, ...  
	- `ALTER DATABASE, ALTER VIEW,` ...

- ###### More Complex Example:
```sql
ALTER PROCEDURE update_items_item_cost
@increase DECIMAL(3, 2),
@vendor_id INT,
@update INT = 0 -- If @update = 1, perform update, else show what would be updated
AS
BEGIN
	IF @update = 1
		UPDATE items
			SET item_cost = item_cost * (1 + @increase)
			WHERE primary_vendor_id = @vendor_id;
	ELSE
		SELECT item_id, vendor_name, primary_vendor_id,item_cost AS existing_cost, item_cost * (1 + @increase) AS proposed_cost
		FROM items As i 
		JOIN vendors AS v
		ON i.primary_vendor_id = v.vendor_id
		WHERE i.primary_vendor_id = @vendor_id;
END
```
- Below is how we call the above procedure:
```sql
EXEC update_items_item_cost 0.50,2,0;
```

###### Cursors
- **Definition**:
	- A **cursor** in SQL is a tool used to **iterate** over a set of rows returned by a query, one row at a time. It allows you to process each row individually, which can be useful when you need to perform complex operations that cannot be easily done in a single SQL statement.


- Cursor Example:
```sql
DECLARE @variable_1 INT
DECLARE @variable_2 DECIMAL (18,2)

DECLARE pmt_cursor CURSOR FOR
SELECT col_1, col_2
FROM table_name

OPEN pmt_cursor
FETCH NEXT FROM pmt_cursor INTO @variable_1,@variable_2

WHILE @@FETCH_STATUS = 0
BEGIN 
	UPDATE table_name
	SET col_1 = col_1 - @variable_1
	WHERE col_2 = @variable_2
	FETCH NEXT FROM pmt_cursor INTO @variable_1,@variable_2
END
CLOSE pmt_cursor
DEALLOCATE pmt_cursor
```

- `@@FETCH_STATUS`
	- Returns the status of the last cursor FETCH  
	- 0 -> fetch status success
	- -1 -> fetch status failed
	- -2 -> row fetched is missing

###### Triggers
- A trigger is a special stored procedure attached to a specific table
- ![[Pasted image 20241129132317.png]]
###### Why Use Triggers?
- Enforce business rules too complex CHECK constraints or referential integrity 
- Automate activity 
- Access or modify other tables 
###### Creating a Trigger
```sql
CREATE TRIGGER trigger_name
ON table_name
AFTER [INSERT][,][UPDATE][,][DELETE]
AS
	optionally declare variables here
BEGIN
	insert statements for trigger here
	```

###### Simple Trigger Example
```sql
USE joins;

ON table_1  
AFTER INSERT  
AS  
	UPDATE table_2  
	SET col_1 = col_1 + 1;
```
