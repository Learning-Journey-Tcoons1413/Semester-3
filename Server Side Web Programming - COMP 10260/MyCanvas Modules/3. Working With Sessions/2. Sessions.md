Sessions provide a way to maintain state information across multiple pages during a user's visit to a website. A session is a temporary storage mechanism that allows storing data that is accessible throughout the $_SESSION superglobal array. Each session is assigned a session id that is passed back and forth between the client and server sides, typically through a cookie, though they are allowed as a URL parameter on systems not supporting cookies.

```php
session_start();
$_SESSION['username'] = 'Hosea';
session_unset();

```
To delete all temporary files from the operating system we use `session_destroy();`

In PHP, both `session_unset()` and `session_destroy()` are used to manage session data, but they perform different tasks:

### 1. `session_unset()`
- **Purpose**: It frees all session variables.
- **How it works**: This function removes all the variables that are stored in the session. It does **not destroy the session itself**, just the data stored within it.
- **Usage**: Typically used when you want to clear the session data without closing the session or invalidating it. After calling `session_unset()`, the session remains active, and you can still use it, just without any previously stored session variables.
```php
session_start(); $_SESSION['user'] = 'John Doe'; session_unset();  
// All session variables are cleared, but the session itself is still valid.
```

### 2. `session_destroy()`
- **Purpose**: It completely destroys the session.
- **How it works**: This function destroys the session on the server side, including all session data, and also invalidates the session ID (removes the session itself).
- **Usage**: It's commonly used when you want to log a user out of your application, as it completely wipes the session and its data.
```php
session_start();
$_SESSION['user'] = 'John Doe';
session_destroy();  
// Destroys the session, including its data, and invalidates the session ID.
```
